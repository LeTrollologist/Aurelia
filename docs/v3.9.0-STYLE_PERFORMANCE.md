# v3.9.0 — Styled-layer performance: content bounds

Status: **implemented and shipped**. This is the design record, updated with the measured result.

## Outcome

`render_styled` / `render_styled_srgb16` now compute the layer's alpha bounds, expand them by the
largest effect support, and evaluate only that rectangle. `render` stays as the full-canvas
reference, and two test modules gate equivalence.

Measured (`bench_styles`, consistent workload, median of 20 after 3 warm-ups):

| Document | Layers | Art | Before | After |
| :--- | --: | :--- | --: | --: |
| 1080p | 1 | large | 129 ms style / 133 ms composite | 79 ms / 83 ms |
| 1080p | 4 | large | 130 / 541 ms | 88 / 382 ms |
| 1080p | 1 | small | 129 / 133 ms | 3 / 8 ms |
| 4K | 1 | large | 551 / 588 ms | 355 / 367 ms |
| 4K | 4 | large | 526 / 2190 ms | 332 / 1457 ms |
| 4K | 1 | small | 551 / 588 ms | 13 / 35 ms |
| 4K | 8 | large | 788 / 6415 ms | 348 / 2843 ms |

Small art drops by roughly two orders of magnitude; large art by 35–55%; full-canvas art is
unchanged by design. Caching was not needed for this result and is deferred.

### What actually landed

- Alpha bounds scan + support expansion (`styled_rect`, `effect_support`), clamped to the canvas.
- Rectangle renderer (`render_rect`) shared by the full-canvas reference and the bounded path, so
  there is one implementation of the effect maths.
- Bounded output is a full layer-sized buffer with transparent pixels outside the rect; the
  compositor already treats alpha zero as no contribution, so this needs no API change.
- Equivalence tests: `bounded_equivalence` (empty, single pixel, corners, edge-touching, full
  canvas, rectangles, 8/16-bit) and `bounded_randomized` (24 deterministic random fixtures).
- `bench_styles` reports small-art and large-art cases, min/median/p95, and raw samples.

### Deviations from the plan

- No mask caching: small-art is single-digit milliseconds; the remaining large-art cost is real
  effect work. Revisit with a many-small-layers profile if needed.
- The output buffer is still layer-sized (only the effect buffers are bounded). Refactoring the
  compositor to carry a sub-rect styled overlay would save the zero-fill, but measurement does not
  justify the API churn yet.
- u8/u16 mask passes were not needed to hit the target.

## Problem

Style rendering is O(canvas × effects). v3.8.1 measurements (`bench_styles`, median of 12):

| Document | Layers | Style render | Viewport |
| :--- | --: | --: | --: |
| 1920×1080 | 1 | 141 ms | 150 ms |
| 1920×1080 | 4 | 121 ms/layer | 508 ms |
| 3840×2160 | 1 | 500 ms | 573 ms |
| 3840×2160 | 4 | 502 ms/layer | 2212 ms |

Large transparent regions are blurred, masked, blended and allocated every composite even when the
artwork occupies a small part of the canvas. The fix is to render each layer's effects only where
they can be nonzero, then composite that sub-rect.

## Bounds

For a layer, compute the alpha bounds `content = [min_x, min_y, max_x, max_y]` over pixels with
alpha > 0 (the stroke silhouette uses its own > 0.5 threshold, so use a superset: alpha > 0).

Effect support, using the current implementation:

- blur: 3 box passes with `kernel = max(1, round(radius / 1.5))` → support `3 · kernel` per axis.
- drop shadow: shifted by `(offset_x, offset_y)`, then blurred → per-axis support
  `|offset| + 3 · kernel`.
- outer glow: masked by `1 − alpha`, then blurred → support `3 · kernel`.
- stroke: outside band of width `width` from the > 0.5 silhouette → support `ceil(width) + 1`.

Expanded bounds = content expanded by the maximum of those supports on each side, with the shadow
offset applied to the correct side, then clamped to the canvas. If the clamped rect equals the
canvas, fall back to the existing path.

Outside the expanded rect every effect mask is exactly zero (by the support calculation), so
cropping is lossless. This is the same argument as a convolution kernel: samples beyond the
support contribute nothing.

## Equivalence requirements

The optimized result must be **bit-identical** to the full-canvas reference, not merely close.

- Keep the current full-canvas renderer as `render_styled_reference` under `cfg(test)` (or a
  private feature), and compare the *composited document* for randomized fixtures. Comparing the
  styled layer buffer alone would flag harmless RGB-in-transparent pixels.
- Use the same transparent-extension policy inside the sub-rect. At the rect border, samples
  outside are zero in both versions; adding/subtracting zero leaves f32 values unchanged, so the
  running sums match exactly. No change to the divisor (always the full kernel).
- Stroke distance is a chamfer transform: initialize the rect's border to "far" and clamp
  coverage to zero outside `width`. Any pixel whose distance exceeds the stroke width contributes
  nothing, so local and global distance agree on the band that matters.
- Include fixtures where art touches each canvas edge, fills the canvas, is a single pixel, sits
  in one corner, has a shadow offset that pushes support outside the canvas, and where the effect
  support is larger than the document. Also cover masks, clipping, 16-bit layers and mixed
  documents.
- Keep the existing blur-policy tests; they must continue to pin transparent extension at canvas
  edges.

If bit-identical fails only through f32 summation order, treat that as a gate failure and fix the
implementation; do not paper over it with an epsilon.

## Allocation and caching

Phase 1: allocate effect buffers at the expanded rect size. A small object on a 4K canvas allocates
a small mask instead of 8 MB f32 planes. No cache yet; measure.

Phase 2: cache per-effect masks keyed by `(alpha hash, style parameters, rect, format)`. Effects
depend only on the layer's alpha, not its RGB, so a fast hash over `w · h` alpha bytes (not the full
RGBA buffer) detects content changes cheaply. Style parameter changes invalidate only that effect.
The cache must be invalidated by undo/redo, painting, masks that affect styling, layer resize and
document close; prefer a per-layer revision counter bumped at mutation sites if it can be made
complete, otherwise hash.

Phase 3: u8/u16 mask passes if profiling still shows the blur dominating; f32 is convenient but
not required for 8-bit masks.

## Benchmark protocol (fixes the v3.8.1 bench)

- Identical workload across layer counts: use the same art generator and identical per-layer
  effect parameters for 1, 2, 4 and 8 layers. The v3.8.1 bench varied the pattern with the layer
  index; that must not be used to compare counts.
- Three warm-up runs, then 20 measured runs; report **raw samples** (JSON/CSV in
  `docs/benchmarks/`) alongside min, median and p95. Keep machine/build metadata in the file.
- Separate cases: small art (realistic), art touching a canvas edge, art filling the canvas (no
  win expected), and empty styles (control).
- Keep `bench_styles` as the harness; the viewport number requires a `render_canvas` pass first
  (the Navigator reads its composite buffer).

## Non-goals

- No new style effects; no GPU work; no change to the boundary policy or visual output.
- No tab/session work in this milestone.

## Rollout

1. Land bounds computation + sub-rect rendering behind the reference-equivalence tests.
2. Benchmark; if small-art cases improve by the expected factor, replace the full-canvas path.
3. Add mask caching only if measurements justify it.
4. Update `docs/PERFORMANCE.md` with raw + median numbers and the workload definition.

## Risks

- Full-canvas art still costs the same → expected; document it rather than claiming a win.
- Many tiny layers could pay per-layer allocation overhead; measure a "many small layers" case.
- Caching can go stale; without a complete revision counter, prefer the alpha hash and keep the
  cache opt-in until proven.
- The 16-bit path promotes 8-bit layers before styling; bounds must be computed on the promoted
  alpha with the same > 0 rule.
