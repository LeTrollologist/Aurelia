# Aurelia v3.13.0-beta.2 - project loading hardening

**This is a prerelease.** It hardens the native project loader; keep v3.12.0 for
production work unless you specifically need these fixes.

## Invalid layer hierarchies are rejected

The loader now validates the complete layer hierarchy before returning a document.
Projects with duplicate layer ids, self-parenting layers, missing or non-group parents,
multi-node cycles, or more than 1024 parent links are rejected with `CorruptData`.

This prevents a malformed `.aur` or `.hcv` project from hanging the compositor. The
visibility, opacity and descendant traversals also carry their own cycle and depth bounds
as defence in depth.

## Document-wide decode budget

Project decoding now enforces aggregate limits across the whole document:

- 4096 layers
- 512 Mi pixels
- 2 GiB of decoded layer storage, including pixel buffers, 16-bit storage, masks,
  text content, font names and layer names

The budget is reserved before each buffer is allocated, so a small compressed project
can no longer request tens of gigabytes by multiplying many layers. The previous
single-layer decompression bound remains in place.

Both changes apply to AUR v1, v2 and v3, and to legacy HCV v3, v4 and v5 projects.

## Verification

- 365 Rust tests passing, 2 ignored (sparse gate and soak).
- `python scripts/quality.py` covers the workspace, release-tool tests, sparse 16-bit
  gate and 120-cycle soak.
- No AUR format bump; existing valid projects continue to load unchanged.

## Distribution

The portable zip and per-user Inno installer are Ed25519-signed and SHA-256 verified.
The installer remains unsigned by Authenticode policy; Windows SmartScreen may warn.

## VirusTotal

No VirusTotal scan was performed for this prerelease because no API key was available in the release environment. No detection verdicts are claimed.
