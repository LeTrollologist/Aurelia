# Aurelia v3.13.0

## What this release means

Aurelia v3.13.0 focuses on production reliability. Existing projects remain compatible, malformed
imports receive stricter validation, project saves have improved durability, and Windows
distribution artifacts now include detached cryptographic signatures and SHA-256 checksums.

The engineering details are below. If you are evaluating the download, prefer the signed portable
zip if you want the smallest trust surface, and verify
[`SHA256SUMS.txt`](https://github.com/LeTrollologist/Aurelia/releases/download/v3.13.0/SHA256SUMS.txt)
and the `.sig` files against the
[public key](https://github.com/LeTrollologist/Aurelia/blob/main/keys/aurelia-publisher-2026.pub)
before running either binary.

## Release engineering

Aurelia v3.13.0 is the production release of the project-loading, save-durability, clipboard,
import and release-metadata hardening work.

## Clipboard DIB limit

Clipboard DIB imports now enforce the same 64-megapixel limit as PNG clipboard imports. Width,
height, stride and the decoded RGBA length use checked arithmetic; oversized or malformed DIBs are
rejected before the pixel buffer is allocated. Existing valid DIB imports are unchanged.

## Owned window state

The `static mut GLOBAL_APP_PTR` is gone. The application state is a `Box` whose pointer is passed
through `CreateWindowExW` and stored in `GWLP_USERDATA`. `WM_NCCREATE` installs the pointer,
`WM_DESTROY` clears and drops it, and the message loop has an explicit fallback cleanup. Message
dispatch cannot read a null or stale global pointer, and teardown releases the window state
deterministically.

## Project and import hardening

- Invalid and cyclic layer hierarchies are rejected with `CorruptData`.
- Project decoding has aggregate limits: 4096 layers, 512 Mi pixels, and 2 GiB of decoded layer
  storage.
- Layer names longer than 65,535 bytes are rejected instead of producing a corrupt project.
- Brush imports have an aggregate 63 Mi pixel / 252 MiB decoded budget.
- Project saves use unique temporary files, `sync_all` before replacement, and cleanup on failure.

## Distribution and verification metadata

- The portable executable carries PE `FileVersion`, `ProductVersion`, `ProductName`,
  `FileDescription` and company metadata.
- `SHA256SUMS.txt` is attached to the release and listed in the assets. Verify it and the detached
  `.sig` files before running either binary.
- `RELEASE_PROCESS.md` documents private-key backup and tested-restore procedures.
- `docs/REPRODUCIBLE_BUILDS.md` records the reproducibility assessment: source builds are
  feasible from the lockfile, but MSVC timestamps, packaging and the absence of an independent
  CI builder mean the published binaries are not bit-for-bit reproducible.
- The installer is not Authenticode-signed; `SECURITY.md` and the release notes disclose this.

## Verification

- 377 Rust tests passing, 2 ignored (sparse gate and soak).
- `python scripts/quality.py` runs formatting, Clippy correctness, the workspace suite, the
  release-tool pytest suite, the sparse-16-bit gate and the 120-cycle soak.
- No AUR format bump; existing valid projects continue to load unchanged.

## Distribution

The portable zip and per-user Inno installer are Ed25519-signed. Verify `SHA256SUMS.txt` and the
detached `.sig` files against the published public key. Windows SmartScreen may warn because
the installer is unsigned by Authenticode.
