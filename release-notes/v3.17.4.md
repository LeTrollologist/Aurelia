# Aurelia v3.17.4

## What this release means

v3.17.4 makes the layer panel's continuous property edits undoable as **coalesced
transactions**. Renaming a layer, dragging the opacity slider, and adjusting an adjustment
layer's sliders previously marked the document dirty but recorded no undo step; a slider drag
could not be undone, and a rename could not be reverted. Each gesture is now a single undo step.

Everything else from v3.17.3 is unchanged.

## Coalesced property transactions

- The panel opens a transaction on interaction start (text focus, slider drag, opening the
  adjustment inspector) and commits it on release, focus loss, inspector close, layer switch or
  save. The whole gesture is one `LayerPropertiesCommand` capturing the layer's name, opacity and
  adjustment configuration before and after.
- A transaction that changed nothing records nothing: clicking into a slider without moving it
  does not add an empty undo entry, and does not mark the document dirty.
- A transaction can never span two layers or two kinds of edit: starting another edit commits
  the open one first.
- Saving commits any open transaction before the saved generation is captured, so a rename made
  and then saved cannot reappear as unsaved work.

## Verification

- 429 Rust tests passing, 2 ignored (five new: opacity drag coalesces to one step, rename
  coalesces, a no-op transaction records nothing, switching layers commits the previous one,
  and an adjustment-inspector session restores the previous values on undo).
- Formatting and Clippy correctness pass.

## Known gaps still open

- Two folder selectors in the layer panel share the same egui id (`group_sel_`); harmless today,
  but it should be made unique.
- The pre-existing `f32` literal fallback warnings remain (future compiler hard errors).
- `scale_canvas` resamples straight alpha rather than premultiplied.

## Distribution

The portable zip and per-user Inno installer are Ed25519-signed. Verify `SHA256SUMS.txt` and the
detached `.sig` files against `keys/aurelia-publisher-2026.pub` before running either binary.
The installer is not Authenticode-signed; Windows SmartScreen may warn. VirusTotal results, if
any, describe only the scanned artifacts and are advisory.
