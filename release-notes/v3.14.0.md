# Aurelia v3.14.0

## What this release means

Aurelia v3.14.0 is a production release. It adds an **experimental, opt-in 10-bit canvas
presentation path** for 16-bit documents on 10-bit displays. The feature is off by default and
must be enabled in **Preferences → Experimental**; the GDI 8-bit path remains the fallback.

Visible 10-bit scanout could not be verified on the release machine, which has an 8-bit display.
The setting says so explicitly. Do not treat this release as a professional-colour or
10-bit-scanout certification.

## 10-bit canvas presentation (experimental)

- Native RGBA16 compositing is converted to packed `R10G10B10A2_UNORM` instead of being reduced
  to 8 bits for the viewport.
- A D3D11 device and DXGI flip-model swapchain present the canvas when the output reports at least
  10 bits per colour.
- Selection tint, tracing reference, onion skins and soft proof are blended in 10-bit space.
  Soft proof uses a cached 16-bit proof transform.
- egui, grid, rulers and guides remain 8-bit and are expanded into the 10-bit frame.
- The path is only selected for **16-bit documents** when the output is 10-bit and the
  experimental setting is enabled. 8-bit documents stay on the existing GDI path.
- Any device, swapchain, texture, resize or present failure falls back to GDI.

The preference is persisted with the other editor preferences and requires an app restart.
`AURELIA_FORCE_10BIT=1` is a hardware-diagnostics override; it bypasses the output and document
gates but still falls back if the presenter cannot be created.

## Performance

Measured with `bench_canvas_present` on the reference machine, best of five runs on a three-layer
16-bit document:

| Document | RGBA8 path | RGBA16 → 10-bit | Overhead |
| :--- | ---: | ---: | ---: |
| 1920x1080 | 47.5 ms | 51.0 ms | 1.07x |
| 3840x2160 | 257.1 ms | 270.5 ms | 1.05x |

The measurement covers canvas rendering, not DXGI upload/present. It is a render-cost comparison,
not a frame-rate guarantee.

## Verification

- 385 Rust tests passing, 2 ignored (soak and the sparse gate); app tests are now included.
- Formatting and Clippy correctness pass.
- GDI fallback remains the default for 8-bit documents and for any 10-bit presenter failure.
- Forced 10-bit path launches and screenshots on the 8-bit reference machine; that proves the
  plumbing, not the visible scanout.

## Known limitations

- Visible banding removal has not been verified on a 10-bit display chain.
- Mixed 10-bit/8-bit monitor and Remote Desktop behaviour still need hardware validation.
- egui/UI remains 8-bit by design.
- The installer is not Authenticode-signed; verify `SHA256SUMS.txt` and the detached `.sig` files
  against the published public key.
- Windows SmartScreen may warn; the portable zip remains available as the smaller trust surface.

## Distribution

The portable zip and per-user Inno installer are Ed25519-signed. Verify the checksum manifest and
the detached signatures before running either binary. The release is production, not a beta.
