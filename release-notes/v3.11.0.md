# Aurelia v3.11.0 — 16-bit integration correctness

A correctness pass over the 16-bit paths that are easy to miss when testing features one at a
time. It found one real bug and pinned the rest with tests.

## Fixed: Copy Merged downconverted to 8 bits

`copy_merged` always called the 8-bit compositor, even in a 16-bit document, and wrapped the
result in an 8-bit clipboard image. Layer copy/cut already preserved RGBA16, so the merged path was
the odd one out: `Ctrl+Shift+C` silently moved a 16-bit document's flattened result onto the 8-bit
lattice before it ever reached the internal clipboard.

Copy Merged now composites at 16 bits when the document is 16-bit **or contains any 16-bit
layer**, applies selection coverage to the 16-bit alpha, and stores the region as
`ClipboardImage::from_rgba16`. The 8-bit document path is unchanged.

## Integration checks pinned

- **Copy Merged preserves sub-lattice values**: a pixel with channels `301/1001/40001` survives
  copy at RGBA16 (new test; it fails against the old path).
- **Copy → paste round-trip** on a 16-bit layer preserves those values and the layer format.
- **Mixed document** (8-bit layer inside a 16-bit document) still merges to a 16-bit clipboard.
- Existing coverage that remains green: 16-bit transforms, filters/adjustments, selection alpha,
  layer styles, mixed-format compositing, AUR save/load and merge-down.

Known 8-bit-by-design paths are unchanged and documented: the viewport presentation, the Windows
DIB clipboard export, animation previews, and image export (native 16-bit PNG remains in the
interop queue). They are not silently downconverting an internal operation; they are display or
interchange boundaries.

## Compatibility

- No format or storage change. 8-bit Copy Merged output is unchanged.
- The internal clipboard gains a 16-bit constructor; the system clipboard still receives 8-bit
  DIBV5.
