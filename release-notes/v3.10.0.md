# Aurelia v3.10.0 — persistence and recovery hardening

This release hardens the project format and crash recovery. No format change; the AUR v3 bytes for
a valid document are unchanged. The work is about what happens when files are truncated, mutated,
over-claim their lengths, or when a save fails halfway.

## Recovery snapshots

Autosave was previously named from the document's file stem only. Two projects called
`poster.aur` in different folders shared one snapshot, and on startup Aurelia only looked for the
current document's path — which on a fresh launch is untitled, so a named project's snapshot was
never offered.

- Snapshot names now include a stable hash of the full document path:
  `<stem>-<path-hash>-autosave.aur` (FNV-1a over the lowercased path, case-insensitive on Windows).
- Startup scans the whole autosave directory, newest first, and offers each snapshot. Restoring
  opens it and consumes that file; declining deletes it and moves to the next one. A corrupt
  snapshot is reported and skipped instead of blocking the others.
- A recovered document is no longer added to Recent Files (it is not a project path).
- Saving also removes the legacy `<stem>-autosave.aur` name, so an upgrade cannot keep offering a
  stale snapshot for a document that has just been saved.

Atomic saves already wrote a sibling `.tmp` and renamed it; a failure now has an explicit test that
the previous file is byte-for-byte untouched.

## Section parsing

The optional editor (`AED1`) and style (`ASTY`) sections are still ignored rather than fatal when
damaged. Their declared counts are now also bounded by the actual payload:

- styles: `count <= 100_000` and every entry needs at least 9 bytes;
- editor guides: `count <= 4096` and every guide needs 5 bytes.

A 1 MiB section can no longer claim a record count that the parser would reserve for before hitting
EOF. Length fields are still capped at their existing 1 MiB limits.

## Corpus and regression tests

New `crates/aurelia-io/tests/persistence_hardening.rs` exercises the writer/reader directly:

- **every truncation** of a document containing editor state and all three layer styles — load
  either succeeds with optional defaults or returns an error; it never panics;
- truncation from the editor section onward still loads the document (optional data degrades);
- **bit flips** across the whole optional tail — no panic;
- **length/count lies** (`u32::MAX`, zero, over-cap) for both sections — the document still loads;
- **save → load → save** is byte-stable, and a reload preserves editor state and styles;
- **failed atomic save** leaves the original file untouched.

The test document is generated by the real writer, so the corpus cannot drift from the format.

## Compatibility

- No AUR version or layer-record change. Valid files saved by v3.9.x load and re-save identically.
- Recovery snapshots from v3.9.x (unhashed names) are discovered by the new scan; saving removes
  them.
- Damaged optional sections remain non-fatal.
