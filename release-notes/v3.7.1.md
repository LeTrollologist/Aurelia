# Aurelia v3.7.1 — clipboard and Adaptive layers

Two workflow features: standard cut/copy/paste, and a blend mode that keeps a layer readable over
whatever sits underneath it.

## Clipboard

**Cut / Copy / Copy Merged / Paste** are on the Edit menu and on
<kbd>Ctrl</kbd>+<kbd>X</kbd> / <kbd>C</kbd> / <kbd>Shift</kbd>+<kbd>C</kbd> / <kbd>V</kbd>.

- **Copy** takes the active raster or text layer through the selection. The payload is the
  selection's pixel bounds, with each pixel's alpha scaled by its coverage — a feathered
  selection produces a feathered payload, and pixels outside it are transparent, matching
  GIMP/Photoshop copy behaviour.
- **Cut** copies first, then clears the same region (also coverage-weighted) as one undoable
  pixel edit.
- **Copy Merged** flattens the visible document with the selection as an alpha mask, for
  copying a composition rather than one layer.
- **Paste** creates a new layer at the copied canvas position and is undoable (`AddLayerCommand`).
  Images pasted from another application are centred on the canvas.

**Precision.** The internal clipboard stores the source storage format, so RGBA16 → RGBA16 paste
keeps native `u16` channels with no 8-bit round trip. The Windows clipboard copy is a separate
8-bit DIBV5 (`BITMAPV5HEADER`, bottom-up BGRA, sRGB) so other applications can paste the image.
If the system clipboard sequence changes between copy and paste, the external image wins;
otherwise the lossless internal payload does. Malformed or compressed DIBs are rejected by the
decoder rather than guessed at.

Layer masks are not part of the payload — a mask is a layer property, not pixels — and
group/adjustment layers have nothing to copy. Those cases report a status message.

Full semantics and limits: [docs/CLIPBOARD_AND_SMART_LAYERS.md](../docs/CLIPBOARD_AND_SMART_LAYERS.md).

## Adaptive layers (auto-contrast blend)

A new **Adaptive** blend mode makes one layer readable over light, dark and busy backdrops. Per
pixel it compares the layer's luminance with the composited backdrop and keeps either the
authored colour or its inverse, whichever has more contrast:

```
keep = |lum_src − lum_dst| >= |(1 − lum_src) − lum_dst|
out  = keep ? src : 1 − src        (then normal alpha compositing)
```

Ties keep the authored colour, so a mid-grey layer on a mid-grey backdrop is not flipped
arbitrarily. Alpha, masks, clipping, opacity and layer order behave exactly as for any other
blend mode, and the adaptation happens at composite time, so previews and exports agree.

**How Adobe/GIMP do it.** The closest existing modes are Difference and Exclusion, which always
invert relative to the backdrop; Adaptive only inverts when that reads better and is driven by
luminance rather than per-channel arithmetic. Photoshop's Smart Objects are unrelated (embedded
non-destructive content), and Colour Overlay is a fixed colour. Adaptive is a blend mode rather
than a hidden layer type: it appears in the layer blend list, persists as the layer blend byte
(v3 value `13`), and unknown values in older builds fall back to Normal.

The mode is documented, with its limits (mid-tone on mid-tone cannot be rescued; it adapts to
what is below, not above), in the same document.

## Compatibility

- AUR v1/v2 load read-only; saves continue to write v3. A layer using Adaptive stores blend byte
  `13`; Aurelia versions before v3.7.1 read that byte as Normal, the same fallback already used
  for unknown blend values.
- No document-format bump and no change to existing blend-mode bytes.
- Clipboard is session-only (one slot), like the system clipboard; pasted layers are ordinary
  layers and can be saved, masked and blended normally.
